# Анализ банковских транзакций в Metabase (BI-аналитика)

Проект по визуализации и анализу личных финансовых данных. В ходе работы была развернута инфраструктура в Docker, сгенерирован реалистичный датасет на Python, проведена предобработка данных с помощью SQL и собран интерактивный дашборд.

## 🛠 Технологический стек
* **BI Платформа:** Metabase
* **База данных:** PostgreSQL 16
* **Инфраструктура:** Docker, Docker-compose
* **Язык подготовки данных:** Python (Pandas, Numpy)
* **Язык запросов:** SQL

---

## 1. Развертывание и подготовка данных

Данные генерируются скриптом `generate_data.py` (1000 транзакций за год) и загружаются в PostgreSQL через контейнер.

### Инфраструктура (Docker-compose)
Используется связка Metabase и PostgreSQL, объединенная в одну сеть `metanet1`. База данных сохраняется в volume `./pg_data`.

### Подготовка данных (SQL)
Для создания модели данных в Metabase использовался следующий SQL-запрос. Он выполняет очистку, приведение типов и расчет финансового результата (`income`):

```sql
SELECT 
    *,
    -- Приведение текстовой даты к формату Date
    TO_DATE(transactiondate, 'DD.MM.YYYY') AS dt,
    
    -- Преобразование суммы в числовой формат
    CAST(amount AS DECIMAL(10,2)) AS value,

    -- Расчет прибыли/убытка: списаниям присваивается отрицательный знак
    CASE 
        WHEN type = 'Списание' THEN CAST(amount AS DECIMAL(10,2)) * -1
        ELSE CAST(amount AS DECIMAL(10,2))
    END AS income,

    -- Очистка и приведение кэшбека
    CAST(REPLACE(bonusValue, '+', '') AS DECIMAL(10,2)) AS bonus_clean

FROM raw_transactions;
```

## 2. Описание визуализаций

### 2.1 Распределение трат (Donut Chart)
* **Логика:** Фильтр `income < 0`.
* **Метрика:** Сумма `income` по категориям.
* **Цель:** Показать долю каждой категории в общих расходах.

### 2.2 Индикатор среднемесячных трат (Gauge)
* **Логика:** Агрегация `Sum(income)` сгруппированная по месяцам, затем расчет `Average`.
* **Цель:** Контроль среднего уровня расходов относительно установленных лимитов.

### 2.3 Анализ кэшбека по категориям (Horizontal Bar)
* **Логика:** Фильтр `bonus_clean > 0`.
* **Метрика:** Сумма `bonus_clean`.
* **Цель:** Определить наиболее выгодные категории покупок.

### 2.4 Приход и Расход по месяцам (Bar Chart)
* **Логика:** Группировка по `dt` (Месяц) и `type`.
* **Метрика:** Сумма `income`.
* **Цель:** Сравнение ежемесячных поступлений и трат.

### 2.5 Движение средств (Cumulative Line)
* **Логика:** Накопительный итог (Cumulative Sum) по колонке `income` за весь период.
* **Цель:** Визуализация динамики остатка на счете.

### 2.6 Траты по месяцам и категориям (Stacked Bar)
* **Логика:** Фильтр `income < 0`, группировка по месяцам и категориям.
* **Цель:** Глубокий анализ изменения структуры расходов в течение года.

## 3. Интерактивность и Кросс-фильтрация

Дашборд настроен для оперативного анализа через:
1. **Глобальные фильтры:** В верхней части дашборда добавлены фильтры по **Дате** и **Категории**, которые связаны со всеми графиками.
2. **Кросс-фильтрация:** Взаимодействие между графиками включено по умолчанию. При клике на категорию (например, "Транспорт") в круговой диаграмме, все остальные отчеты (кэшбек, динамика, расходы) автоматически перестраиваются для отображения данных только по этой категории.

## 4. Как запустить проект
1. Склонировать репозиторий.
2. Выполнить `docker-compose up -d`.
3. Запустить `python3 generate_data.py`.
4. Импортировать CSV в Postgres (команды импорта доступны в истории терминала в этом репозитории).
5. Подключить Metabase к Postgres (localhost:3000).
